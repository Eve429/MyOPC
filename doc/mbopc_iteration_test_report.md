| 外轮廓越入孔洞 | hole 关系失败，整轮回滚；通过 |
| 矩形左边越过右边 | ring 绕向改变，整轮回滚；通过 |
| 斜边跨多个 core | 最终全局重建连续，无 core 裁剪损失；通过 |
| inner/outer 冲突 | ambiguous 增加，方向为 0；通过 |
| target 缓存命中 | 首次/命中均为 `uint8 [0,255]` 且一致，设备边界统一归一化；通过 |
| 单次迭代提交 | `iterations=1` 评价初态、发布一次合法更新并评价更新态；通过 |
| 最后候选拓扑 | 最后一次允许更新同样经过全局重建校验，非法时回滚；通过 |
| raster 统一方向 | Geometry/OPC 公共返回数组逐像素同向，非对称 PNG 只在输出边界翻转；通过 |

## 3. 完整 `gcd_45nm` CUDA 流程

配置处理 870 cores、223,553 segments、880,801 context memberships，运行 3 轮：

| 轮次 | EPE | L2 | PVBand | valid probes | ambiguous | moved |
|---:|---:|---:|---:|---:|---:|---:|
| 0 | 129,645 | 1,038,629.525 | 115,627.016 | 223,298 | 51 | 129,594 |
| 1 | 74,592 | 563,335.526 | 134,541.151 | 223,298 | 5 | 74,587 |
| 2 | 48,348 | 440,251.433 | 147,187.144 | 223,298 | 2 | 48,346 |

EPE 与 L2 下降；PVBand 上升，已原样记录。结果与重构前历史运行数值一致。

常驻 segment 数组为 5,003,436 bytes，完整 problem 数组为 9,802,180 bytes。GPU 峰值分配 267,334,656 bytes；总耗时 79.834 s，结果 Region 合法，GDS/JSON/PNG 成功生成，且没有全流程 NPZ。

## 4. 内存结论

当前实测设备只有 4 GiB 显存仍能完成该版图；算法不会把整张 reticle 曝光 tensor 常驻 GPU。24 GiB GPU、64 GiB RAM 的目标机器有更大 batch/缓存余量，但最大可处理 reticle 仍取决于 segment/轮廓 CPU 常驻数组和运行时间，不能由单个样例宣称无限规模。

## 5. 最终结论

架构减法没有改变 3 轮数值结果或 GPU 峰值；它显著降低输入常驻内存并改善前端耗时。同步轮次、跨 core 唯一 owner 和拓扑回滚均由回归测试覆盖。

2026-08-12 的契约修复改变了 simple MB-OPC 的轮次含义：历史表格记录的是旧实现的三个已评价状态，不能直接当作“修复后提交三次更新”的新性能基线。新实现需以本次完整回归和后续真实版图复跑为准；旧数据保留用于说明当时的资源规模，不虚构数值等价。
