## 1. 项目整体介绍

### 1.1 MyOPC 是什么

MyOPC 是面向半导体光刻 **OPC（光学邻近效应修正）** 的高性能层级版图与几何基础。当前已实现的完整链路是 **MB-OPC（基于模型的 OPC）**：把一张 GDS/OASIS 版图读入一次，构造一套紧凑的、批处理的 NumPy/KLayout 结构，然后流式地按 core（瓦片）+ halo（光学上下文）跑光刻模型、计算 EPE（边缘放置误差）误差、迭代移动边段，最后做一次全局矢量重建输出修正后的版图。

完整链路分层：

```
layout  →  geometry  →  opc.input  →  opc.input.edge  →  opc.iteration.mbopc
                                              ↑                  ↓
                                         opc.diagnostics   lithography + evaluation
```

- **`layout/`**：只读、保留层级的 GDS/OASIS 数据库；ROI/层查询返回 KLayout 原生 `Region`，绝不扁平化整张层级。
- **`geometry/`**：方法无关的 Region ↔ 轮廓 ↔ 数学边转换、Patch 裁剪/拼接、栅格化、校验。
- **`opc/input/`**：MB-OPC 与未来 ILT 共享的输入基础：`PhysicalMask`、规则 core 网格。
- **`opc/input/edge/`**：MB-OPC 专属：边段切分、唯一 owner、探针坐标、全局矢量重建。公共入口是 `prepare_problem()`。
- **`opc/iteration/mbopc/`**：simple MB-OPC 的流式同步迭代求解器 `optimize()`。
- **`lithography/`**：可独立替换的光刻模型；当前为 OpenILT ICCAD13 Hopkins 三工艺角模型。
- **`evaluation/`**：L2、PVBand、EPE 评价指标。
- **`opc/diagnostics.py`**：只在显式请求时才执行的 NPZ/GDS/PNG/几何图集物化。
- `opc/iteration/`（顶层）、`lithography/`、`evaluation/` 是可替换层；光学模型与优化器**不得**写进 `opc.input`。

### 1.2 核心数据流（端到端）

```
GDS/OASIS 文件
   │  LayoutDB.open()          （只读、保留层级、单次读取）
   ▼
ShapeQuery.materialize() → RegionBatch     （每层一个 kdb.Region，裁到 ROI）
   │  ★ 必须在 with LayoutDB.open(...) 上下文内完成 ★
   ▼
normalize_physical_mask() → PhysicalMask    （合并、清属性、恢复孔洞；仅保留 Region）
   ▼
extract_contour() → ContourBatch             （Polygon/Ring 两级 CSR）
   ▼
fragment_edges() → SegmentBatch             （最小 edge cache + 控制边段 + 外法向）
   ▼
_build_ownership() → owner/membership CSR   （prepare_problem 私有步骤）
   ▼
prepare_problem() → MBOPCProblem            （grid 与归属直接进入完整问题）
   │
   │  ┌─────────────── 每轮迭代（opc.iteration.mbopc.optimize）───────────────┐
   │  │ 1. 所有 batch 只读同一份全局 current 位移                              │
   │  │ 2. 每个 core：栅格化 target/current mask → 光刻模型 → EPE/L2/PVBand    │
   │  │ 3. owner 唯一写 next_values；halo 只读、不计分                          │
   │  │ 4. 全部 batch 完成 → 拓扑守卫 → 屏障发布 current=next_values            │
   │  └──────────────────────────────────────────────────────────────────── ┘
   ▼
reconstruct_region(problem, best_displacements) → kdb.Region   （只做一次全局重建）
   ▼
summary.json / 结果 GDS / 诊断 PNG
```

### 1.3 必记的关键不变量（违反即出错）

1. **原生 Region 生命周期**：`materialize()` 返回的 `kdb.Region` 仍绑定打开的数据库。因此 `materialize()` 与 `prepare_problem()` **都必须在 `with LayoutDB.open(...)` 上下文内执行**。离开上下文后这些 Region 会变空/零计数。`prepare_problem` 构建出独立的 NumPy/Region 数据后，DB 才可关闭。
2. **参考 vs 迭代状态**：`MBOPCProblem` 是冻结的，其内部数组视为**只读参考**；所有优化状态只放在一个与全局 segment 下标对齐的一维 `displacements` 数组里。
3. **owner-only 写 + 屏障发布**：一个 segment 只有一个 owner core；非 owner core 只能经 halo 只读。所有 core 完成且全局拓扑合法后，才统一发布 `d_next`，禁止边算边覆盖本轮状态。
4. **零位移重建 XOR == 0**：对全零位移做一次 `reconstruct_region`，其结果与原始物理 mask 的异或面积必须为 0（这是重建正确性的总闸门，几何图集会断言）。
5. **物理长度必须能由版图 DBU 精确表达**：命令行的 nm 参数若不能整除为整数 DBU，会直接报错（避免相邻 tile 用不同物理晶格）。
6. **诊断默认关闭**：NPZ/PNG/GDS/几何图集只在显式请求时才物化；不进入迭代热路径。

### 1.4 快速上手（三条命令）

```bash

python run_mbopc_frontend.py

# (2) 完整 MB-OPC（含真实光刻模型 ICCAD13 + 流式迭代 + 全局重建）
python run_mbopc.py                              # 默认跑 TestReticle/simple.gds
python run_mbopc.py TestReticle/gcd_45nm.gds --layer 11/0 --device cpu

# (3) 单独的 Layout/Geometry 查询与导出
python run_layout_geometry.py TestReticle/gcd_45nm.gds --layer 11/0 --arrays --json
```

## 3. layout/ — 层级版图只读数据库

> **受保护目录**。新 OPC 工作只调用其公共接口，不修改其实现。核心思想：版图只读一次、保留层级、按 ROI 局部物化，绝不扁平化整张版图。

### 3.1 `layout/__init__.py` — 公共导出

集中导出本包的稳定公共 API：`LayoutDB`、`ShapeQuery`、`PatchWriter`、`HierarchySummary`/`CellInfo`、数据类型（`DbuBox`/`LayerSpec`/`CellRef`/`RegionBatch`/`LayerShapeStats`/`MaterializationStats`）、以及全部异常。**外部代码应只从 `layout` 顶层导入，不深入子模块。**

### 3.2 `layout/types.py` — 共享不可变数据约束

模块职责：版图查询与几何批次共享的小型不可变数据结构。所有结构体均为 `@dataclass(frozen=True, slots=True)`。

#### `DbuBox`（轴对齐矩形，整数 DBU 坐标）
版图与几何层通用的整数坐标矩形，是 ROI、core、bbox 的统一表达。`order=True` 使其可排序（用于稳定输出）。
- `left: int` — 矩形左边界（DBU）。
- `bottom: int` — 矩形下边界（DBU）。
- `right: int` — 矩形右边界（DBU）。
- `top: int` — 矩形上边界（DBU）。
- 校验：四值必须为整数；`left < right` 且 `bottom < top`（正面积），否则 `ValueError`/`TypeError`。
- 属性 `width -> int` — `right - left`。
- 属性 `height -> int` — `top - bottom`。
- 属性 `area -> int` — `width * height`（DBU²）。
- 方法 `expanded(margin: int) -> DbuBox` — 四边向外扩 `margin` DBU 的新矩形（halo 构造用）。`margin` 需非负整数。
- 方法 `intersection(other: DbuBox) -> DbuBox | None` — 正面积交集；分离或仅接触返回 `None`。
- 方法 `to_native() -> kdb.Box` — 转原生 `kdb.Box`（仅在进入 KLayout 批处理边界时调用）。
- 类方法 `from_native(box: kdb.Box) -> DbuBox` — 由原生 Box 构造；空 Box 报错。

#### `LayerSpec`（GDS/OASIS 层标识）
- `layer: int` — 层号。
- `datatype: int = 0` — 数据类型，默认 0。
- 校验：非负整数；进入 KLayout 前拒绝非法层号。
- 可排序（用于稳定顺序）。

#### `CellRef`（稳定 Cell 引用）
不暴露可变原生 `kdb.Cell` 的轻量引用。
- `name: str` — Cell 名称。
- `index: int` — KLayout 内部 cell 索引。

#### `LayerShapeStats`（ROI 图形诊断计数）
局部迭代器返回图形的可选诊断计数（`diagnostics=True` 时才统计）。
- `polygon_like: int = 0` — Box/Path/Polygon 数量。
- `text: int = 0` — Text 数量。
- `edge: int = 0` — Edge 数量。
- `other: int = 0` — 其它图形数量。

#### `MaterializationStats`（物化诊断）
- `elapsed_seconds: float` — 原生物化耗时。
- `shapes: Mapping[LayerSpec, LayerShapeStats]` — 各层诊断；构造后冻结为只读映射，防止调用方篡改。

#### `RegionBatch`（局部原生 Region 批次）
统一顶层坐标系、按 Layer 索引的局部 Region 批次。`materialize()` 的返回类型。
- `regions: Mapping[LayerSpec, kdb.Region]` — 各层的原生 Region；只复制小的映射，Region 数据仍留在 C++ 内存。
- `query_box: DbuBox` — 本次查询的 ROI。
- `cell: CellRef` — 所属顶层 Cell。
- `stats: MaterializationStats | None = None` — 可选诊断。
- 属性 `layers -> tuple[LayerSpec, ...]` — 按确定顺序返回所含层。
- 方法 `region(layer: LayerSpec) -> kdb.Region` — 返回指定层原生 Region；缺层抛 `KeyError`。**注意：返回的 Region 仍绑定打开的 DB（见不变量 1）。**
- 方法 `counts() -> Mapping[LayerSpec, int]` — 用原生元数据返回各层 Polygon 数。

### 3.3 `layout/database.py` — `LayoutDB`

模块职责：层级 KLayout 数据库的单次加载、只读生命周期管理。

#### `LayoutDB`（只读版图持有者）
在一次 OPC 任务生命周期内唯一持有只读原生版图。**必须用 `LayoutDB.open(...)` 构造，并用上下文管理器 `with` 使用。**

构造与生命周期：
- `__init__(layout, source_path, top_cell)` — 由已解析的原生版图初始化（一般不直接调用，用 `open`）。建立 layer→index 映射。
- 类方法 `open(path, top_cell=None) -> LayoutDB` — **唯一推荐入口**。只解析一次 GDS/OASIS；`top_cell=None` 时要求恰好一个顶层 Cell，否则 `AmbiguousTopCellError`；指定名称找不到则 `CellNotFoundError`；文件读失败 `LayoutOpenError`。
- 属性 `source_path -> Path` — 规范化源文件路径。
- 属性 `dbu_um -> float` — 每个 DBU 对应的微米值（仅供换算/报告）。
- 属性 `top_cell -> CellRef` — 已选顶层 Cell 引用。
- `layers() -> tuple[LayerSpec, ...]` — 按序列出所有已有层。
- `cell(name: str) -> CellRef` — 按精确名称解析 Cell；找不到抛 `CellNotFoundError`。
- `bbox(cell=None) -> DbuBox | None` — Cell 的层级包围盒；空 Cell 返回 `None`。
- `hierarchy_summary() -> HierarchySummary` — 只读层级元数据，不物化图形。
- `query(layers, box, cell=None, preserve_properties=False) -> ShapeQuery` — 校验元数据后创建**惰性**查询。`layers` 接受 `LayerSpec` 或 `(layer, datatype)` 元组的序列；`box` 为 ROI；`preserve_properties` 启用属性保留（见 `ShapeQuery`）。
- `close() -> None` — 释放原生版图；此后惰性查询安全失败。
- `__enter__`/`__exit__` — 上下文管理器，退出时自动 `close()`。
- 私有 `_assert_open()` — DB 关闭后立即 `ClosedLayoutError`，避免惰性查询访问失效对象。`_native_layout`/`_native_cell`/`_native_layer_index` 仅供同级模块使用，不作为公共算法接口。

> **关键**：`query()` 只创建惰性描述，真正的图形物化发生在 `ShapeQuery.materialize()`。后者返回的 `Region` 依赖 DB 仍打开。

### 3.4 `layout/query.py` — `ShapeQuery`

模块职责：层级 ROI 惰性查询以及原生 Region 局部物化。

#### `ShapeQuery`（惰性查询描述）
- `database: object` — 所属 `LayoutDB`（按对象传入，避免循环导入）。
- `cell: CellRef` — 查询的 Cell。
- `layers: tuple[LayerSpec, ...]` — 查询层（已规范化）。
- `box: DbuBox` — 查询 ROI。
- `preserve_properties: bool = False` — 是否在裁剪时保留 Polygon 属性。

方法：
- `materialize(diagnostics=False) -> RegionBatch`
  - **功能**：通过 KLayout C++ 递归迭代器按层物化可转为 Polygon 的图形，裁到 ROI，返回 `RegionBatch`。这是层级遍历的唯一发生点。
  - **输入**：`diagnostics` 为 True 时额外统计 ROI 内 Box/Path/Polygon/Text/Edge。
  - **输出**：`RegionBatch`（含各层裁剪后的原生 Region）。
  - **实现要点**：递归迭代、实例变换、Region 构造全在 C++ 内；Python 每层只发起一次批量调用；用 `shape_flags` 过滤掉 Text（避免计数与多边形遍历不一致）；`preserve_properties` 时用 `Region.NoPropertyConstraint` 做属性保留式相交。**返回的 Region 绑定打开的 DB（不变量 1）。**
  - **异常**：DB 已关闭抛 `ClosedLayoutError`。
- 静态方法 `_collect_shape_stats(...)` — 诊断用：统计与 ROI 接触的图形分类计数（含零面积 Text）。

### 3.5 `layout/layer.py` — `normalize_layers`

#### `normalize_layers(layers) -> tuple[LayerSpec, ...]`
- **功能**：规范化、去重并排序外部传入的层描述。只处理元数据，不读图形。
- **输入**：`layers` — `LayerSpec` 或 `(layer, datatype)` 元组的可迭代对象。
- **输出**：去重排序后的 `LayerSpec` 元组。
- **异常**：空序列抛 `ValueError`。

### 3.6 `layout/hierarchy.py` — 层级快照

模块职责：只读层级检查；正式计算路径不在此扁平化。

#### `CellInfo`（紧凑 Cell 元数据）
- `ref: CellRef` — Cell 引用。
- `bbox: DbuBox | None` — Cell 包围盒；空则 `None`。
- `child_cells: tuple[CellRef, ...]` — 子 Cell 引用。
- `instance_records: int` — 实例记录数。
- `logical_instances: int` — 逻辑实例数（AREF 按阵列展开计）。

#### `HierarchySummary`（不复制图形的层级快照）
- `top_cells: tuple[CellRef, ...]` — 顶层 Cell。
- `cells: tuple[CellInfo, ...]` — 全部 Cell 元数据。

#### `build_hierarchy_summary(db: LayoutDB) -> HierarchySummary`
- **功能**：读取 Cell 与实例记录，生成只读层级快照，**不触碰任何图形存储**。
- **输入**：`db` — 打开的 `LayoutDB`。
- **输出**：`HierarchySummary`。
- **注**：当前 OPC 不读层级做计算（见 `doc/design_review.md` 3.5/4.6），层级只用于统计与未来 planner。

### 3.7 `layout/writer.py` — `PatchWriter`

模块职责：补丁式 GDS/OASIS 原子写出；源版图数据库始终保持只读。

#### `PatchWriter`
- 类常量 `_FORMATS` — 后缀→格式名映射（`.gds/.gds2→GDS2`，`.oas/.oasis→OASIS`）。
- 类方法 `write(patches, output_path, dbu_um, top_name="OPC_PATCHES") -> Path`
  - **功能**：原子写出只含 Patch 的流文件，返回规范化路径。序列化位于全局坐标系、已完成 ownership 裁剪的 `PatchSet`。
  - **输入**：`patches: PatchSet`；`output_path`（后缀须合法）；`dbu_um`（正数）；`top_name`（非空）。
  - **输出**：规范化后的输出 `Path`。
  - **可靠性**：临时文件与目标同目录同卷，`kdb.Layout.write` 完成后用 `os.replace` 原子替换；异常时清理临时文件。
  - **异常**：后缀非法 `ValueError`；目录不存在 `FileNotFoundError`。

### 3.8 `layout/errors.py` — 异常体系

- `LayoutError(RuntimeError)` — 所有版图异常基类。
- `LayoutOpenError` — 版图无法打开或解析。
- `AmbiguousTopCellError` — 多顶层 Cell 且未指定。
- `CellNotFoundError` — 请求的 Cell 不存在。
- `LayerNotFoundError` — 请求的 layer/datatype 不存在。
- `ClosedLayoutError` — 继续使用已关闭的 `LayoutDB`。

## 4. geometry/ — 方法无关的几何转换

> **受保护目录**。提供 Region↔两级 CSR 轮廓、Patch 拼接、栅格化、校验。这些能力方法无关，MB-OPC 与未来 ILT 都可复用；数学边缓存属于 `opc.input.edge`，不进入通用几何层。

### 4.1 `geometry/__init__.py` — 公共导出

导出：`extract_contour`、`extract_contours`、`contours_to_region`、`PatchSet`、`GeometryPatch`、`render_region_batch`、`render_layout_region`、`validate_contours`、类型（`ContourBatch`/`ValidationReport`/`ValidationIssue`）与异常。

### 4.2 `geometry/types.py` — 紧凑数组契约

模块职责：紧凑 NumPy 几何数据契约与不可变 Patch 描述。类型别名 `IntArray=NDArray[int64]`。

#### `ContourBatch`（Polygon/Ring 两级 CSR）
用连续整数数组保存全部 Polygon 的 hull + hole 环，不重复保存 Layer。
- `vertices: IntArray` — 形状 `(N, 2)`，全部环的顶点坐标（DBU）。
- `ring_offsets: IntArray` — 长度 `ring_count+1`，每环在 `vertices` 中的起始偏移；首项 0、末项为顶点总数、单调递增。
- `polygon_ring_offsets: IntArray` — 长度 `polygon_count+1`，每个 Polygon 的 ring 范围；首 ring 是 hull，其余是 hole。
- 校验：顶点二维、两级 offsets 起 0/终目标数量、每环≥3 顶点、每 Polygon≥1 ring。
- 属性 `ring_count -> int` — 环总数（hull+hole）。
- 属性 `polygon_count -> int` — `len(polygon_ring_offsets)-1`。

#### `ValidationIssue`（一条校验问题）
- `code: str` — 问题代号（`zero_length_edge`/`zero_area_ring`）。
- `message: str` — 人类可读说明。
- `layer: LayerSpec` — 所属层。
- `indices: tuple[int, ...] = ()` — 相关索引（顺序稳定，便于测试/报告）。

#### `ValidationReport`（校验汇总）
- `issues: tuple[ValidationIssue, ...] = ()` — 全部问题。
- 属性 `is_valid -> bool` — 无任何问题时为 True。

#### `GeometryPatch`（单 core 单层结果）
- `patch_id: str` — Patch 标识（非空）。
- `layer: LayerSpec` — 所属层。
- `region: kdb.Region` — 该 Patch 的 Region（须为 KLayout Region）。
- `ownership_box: DbuBox` — 负责 core 的 ownership 矩形。

### 4.3 `geometry/contour.py` — Region↔轮廓

模块职责：原生 Region 与连续轮廓数组之间的一次性转换。

#### `extract_contours(batch: RegionBatch) -> Mapping[LayerSpec, ContourBatch]`
- **功能**：仅物化一次每层 Region 的边界，供后续多轮数值 OPC 复用。每层调用 `extract_contour`。
- **输入**：`RegionBatch`。
- **输出**：层→`ContourBatch` 的只读映射（CSR 风格 hull/hole 环）。
- **实现**：逐 Polygon 提取 hull 与全部 hole，并记录每个 Polygon 的 ring 终点。

#### `extract_contour(region) -> ContourBatch`
- **功能**：把一个规范 Region 转为 Polygon/Ring 两级 CSR，是边段准备的单 Region 快速入口。

#### `contours_to_region(contours: ContourBatch) -> kdb.Region`
- **功能**：在保留 Polygon 孔洞拓扑的前提下重建原生 Region。
- **输入**：`ContourBatch`。
- **输出**：`kdb.Region`。
- **实现**：每个 `polygon_ring_offsets` 范围的首 ring 构造 hull，后续 ring 插入为 hole。

#### `_ring_points(contours, ring_id) -> list[kdb.Point]`（私有）
- **功能**：仅在原生重建边界上，把一个环转为 `kdb.Point` 列表。

### 4.4 `geometry/patch.py` — `PatchSet`

模块职责：版图输出前执行考虑 ownership 的 Patch 规范化。

#### `PatchSet`（ownership 不重叠 Patch 集合）
- `__init__()` — 创建空集合。
- `add(patch: GeometryPatch) -> GeometryPatch`
  - **功能**：按 ownership 裁剪输入 Patch，拒绝重复 ID 与同层 ownership 正面积重叠，返回裁剪后的规范化 Patch。
  - **输入**：`GeometryPatch`（其 Region 可跨多个 core，但只拥有 `ownership_box` 内部分）。
  - **输出**：裁剪后的 `GeometryPatch`（已被精确相交到 ownership_box）。
  - **正确性**：相邻 core 对同一图形两部分既不丢失也不重复；仅共享边界不算冲突。
  - **异常**：重复 ID 或 ownership 重叠抛 `PatchConflictError`。
- 属性 `layers -> tuple[LayerSpec, ...]` — 至少含一个 Patch 的层。
- `region(layer) -> kdb.Region` — 拼接指定层已裁剪片段（返回副本）。
- `__len__()` — Patch 数量。
- `__iter__()` — 按 (layer, ownership_box, id) 稳定顺序迭代。

### 4.5 `geometry/raster.py` — 灰度 PNG 栅格化

模块职责：把 planner 局部区域栅格化为可展示/保存的灰度像素图。注意：本模块产**顶部朝上**的 PNG（图片第 0 行在顶）；与 `opc/input/raster.py`（第 0 行在底、供光刻模型）方向相反，两者不可混用。

模块常量：`_MAX_STRIPE_PIXELS = 1_000_000`（分块临时像素上限）、`_DEFAULT_MAX_PIXELS = 64_000_000`（默认最大像素）。

#### `_pixel_size_dbu(dbu_um, pixel_size_nm) -> int`（私有）
- **功能**：把物理像素尺寸精确换算为整数 DBU。
- **异常**：不能精确表达时抛 `RasterizationError`。

#### `_image_shape(box, pixel_dbu, max_pixels) -> tuple[int, int]`（私有）
- **功能**：计算向右上补齐的图片尺寸 `(height, width)`，分配前做内存保护。
- **异常**：超 `max_pixels` 抛 `RasterizationError`。

#### `_raster(region, box, pixel_dbu, shape) -> NDArray[uint8]`（私有）
- **功能**：分块调用原生面积栅格器，转为顶部朝上的 8 位灰度（覆盖率 0–255）。分块避免大 ROI 一次生成海量 Python float。

#### `_save_png(pixels, output_path) -> Path`（私有）
- **功能**：目标目录内原子保存 8 位灰度 PNG。

#### `render_region_batch(batch, layer, dbu_um, pixel_size_nm=5.0, *, output_path=None, show=False, max_pixels=...) -> NDArray[uint8]`
- **功能**：把已提取批次中的单层区域显示或保存为灰度 PNG，并返回像素数组。
- **输入**：`batch: RegionBatch`；`layer`（须在批次内）；`dbu_um`；`pixel_size_nm`；可选 `output_path`/`show`/`max_pixels`。
- **输出**：`uint8` 灰度数组（顶部朝上）。
- **实现**：局部裁剪后显式 `merged()`，避免重叠 Polygon 重复计面积。
- **异常**：缺层抛 `RasterizationError`。

#### `render_layout_region(database, box, layer, pixel_size_nm=5.0, *, output_path=None, show=False, max_pixels=...) -> NDArray[uint8]`
- **功能**：从已打开版图提取单层 planner 区域，直接显示/保存灰度 PNG。
- **输入**：`database: LayoutDB`（须打开）；`box: DbuBox`；`layer`；其余同上。
- **输出**：灰度数组。
- **依赖**：内部 `database.query([layer], box).materialize()` → `render_region_batch`。

### 4.6 `geometry/validate.py` — `validate_contours`

#### `validate_contours(contours: ContourBatch) -> ValidationReport`
- **功能**：在昂贵的 OPC 迭代或原生修复前，检测退化轮廓环。**不修改输入**。
- **检测项**：零长边（环内相邻重复点）、零面积环、每 Polygon 恰一个 hull。
- **输入**：`ContourBatch`。
- **输出**：`ValidationReport`。
- **注意（见 `doc/design_review.md` 4.3）**：本函数**不保证** hole 完整位于 hull 内、外边不越内边、左右穿越、新旧拓扑不变——这些更严格的不变量由求解器的 `_preserves_reference_topology` 守卫。

### 4.7 `geometry/errors.py` — 异常体系

- `GeometryError(RuntimeError)` — 所有几何异常基类。
- `PatchConflictError` — 同层两个 Patch ownership 重叠。
- `RasterizationError` — 区域无法按请求物理像素规则栅格化。

## 5. opc/input/ — OPC 共享输入基础

> MB-OPC、ILT 与后续方法共同复用的输入层。定义物理 mask 与规则 core 网格，方法无关。

### 5.1 `opc/input/__init__.py` — 公共导出

导出：`PhysicalMask`、`normalize_physical_mask`、`CoreSpec`、`RectilinearCoreGrid`。

### 5.2 `opc/input/types.py` — 规则 core 网格契约

模块职责：OPC 方法共享的规则 core 网格数据契约。类型别名 `IntArray/Int32Array/FloatArray`；私有辅助 `_vector`/`_points` 做规范化与校验。

#### `CoreSpec`（单个 core 的输出范围 + 查询范围）
- `core_id: str` — core 标识（非空，如 `"r0c1"`）。
- `ownership_box: DbuBox` — 该 core **唯一负责写出**的范围。
- `context_box: DbuBox` — 包含光学上下文（halo）的查询范围。
- 校验：`core_id` 非空；`context_box` 必须从四方向完整包住 `ownership_box`。

#### `RectilinearCoreGrid`（规则正交网格）
用有序切线定义、可含非等宽边缘 core 的规则正交网格。是 owner 分配与 halo 计算的基础。
- `x_cuts: IntArray` — x 方向切线（严格递增，长度≥2）。
- `y_cuts: IntArray` — y 方向切线（严格递增，长度≥2）。
- `halo_dbu: int = 0` — halo 半宽（非负整数 DBU）。
- 校验：每轴≥2 条切线、严格递增、halo 非负。
- 属性 `column_count -> int` — x 方向 core 数（`len(x_cuts)-1`）。
- 属性 `row_count -> int` — y 方向 core 数。
- 属性 `core_count -> int` — core 总数（`column_count*row_count`）。
- 属性 `bounds -> DbuBox` — 全部 ownership core 覆盖的整体范围。
- 方法 `cores() -> tuple[CoreSpec, ...]`
  - **功能**：按先行后列的稳定顺序生成全部 core 与 halo 描述。
  - **输出**：`CoreSpec` 元组；每个 core 的 `context_box = ownership_box.expanded(halo_dbu)`。
- 方法 `locate_points(points) -> Int32Array`
  - **功能**：向量化返回每个点所属 core 的扁平下标，范围外点用 `-1`。
  - **输入**：`points` — `(N,2)` 浮点坐标。
  - **输出**：`int32` 数组（`row*column_count + column`）。
  - **归属规则（关键）**：内部共享边界用半开区间稳定归右侧/上侧 core；版图最大外边界归最后一列/行，避免最外沿边段无 owner。这正是 `MBOPCProblem.owner_indices` 的来源。

### 5.3 `opc/input/mask.py` — 物理 mask 规范化

模块职责：把版图局部数据规范化为各 OPC 方法共享的物理 mask 边界。

#### `PhysicalMask`（不可变物理 mask）
各 OPC 方法共享的最小单层物理输入。
- `layer: LayerSpec` — 所属层。
- `region: kdb.Region` — 合并后的物理覆盖 Region（固定参考）。
- `query_box: DbuBox` — 来源 ROI。

#### `normalize_physical_mask(batch: RegionBatch, layer: LayerSpec) -> PhysicalMask`
- **功能**：消除内部切割线、恢复孔洞，不提前构造特定 OPC 方法的边段数据。
- **输入**：`batch: RegionBatch`、`layer`。
- **输出**：`PhysicalMask`。
- **步骤**（每一行注释解释“为什么”）：
  1. `batch.region(layer).dup()` — 在副本上操作，不改查询结果。
  2. `region.remove_properties()` — Shape 属性会阻止相接区域合并；先删属性，避免不同属性把内部 cut-line 留下。
  3. `region.min_coherence = True; region.merged()` — 最小连通规则保留仅角点接触的区域为不同 Polygon；显式合并会把 GDS 为表达孔洞引入的零宽桥接线恢复成 hull/hole，使两条重合反向桥边不进入提边。
  4. `has_valid_polygons()` 检查，非法抛 `PhysicalMaskError`。
  5. 返回只含 Layer/Region/ROI 的 `PhysicalMask`；数值轮廓由实际边段调用方提取。

### 5.4 `opc/input/raster.py` — 光刻画布栅格化

模块职责：为 OPC/ILT 的固定画布光刻输入提供原生 Region 栅格化。**注意方向**：本模块第 0 行对应**低 Y**（与探针坐标 `(y-bottom)/pixel` 一致），**不**做 PNG 的上下翻转——与 `geometry/raster.py`（顶部朝上）相反，专供光刻模型，不可混用。

#### `rasterize_region_canvas(region, box, pixel_dbu, canvas) -> NDArray[float32]`
- **功能**：把全局 Region 的局部框栅格化到左下对齐的固定方形画布 `(canvas, canvas)`。
- **输入**：`region: kdb.Region`；`box: DbuBox`（局部框）；`pixel_dbu`（正整数像素尺寸）；`canvas`（正整数画布边长）。
- **输出**：`(canvas, canvas)` 的 `float32` 覆盖率数组（`[0,1]`），局部内容填在左下 `[:height, :width]` 块。
- **实现**：裁剪 box 后 `merged()`，用原生 `rasterize` 得覆盖面积、除以像素面积并 clip 到 `[0,1]`。
- **异常**：`pixel_dbu`/`canvas` 非正整数、或局部框所需像素超过画布，抛 `ValueError`。

#### `ownership_canvas(core, context, pixel_dbu, canvas) -> NDArray[bool_]`
- **功能**：按像素中心生成 core 的唯一计分区域布尔画布，halo 像素保持 `False`。
- **输入**：`core: DbuBox`（ownership 矩形）；`context: DbuBox`（须四向包含 core）；`pixel_dbu`；`canvas`。
- **输出**：`(canvas, canvas)` 的 `bool` 数组；像素中心落在 `[core.left, core.right) × [core.bottom, core.top)` 内为 True。
- **用途**：评价时只在 ownership 像素累计 L2/PVBand，halo 只提供光学上下文不计分（见不变量 3）。
- **异常**：`context` 不包含 `core` 抛 `ValueError`。

## 6. opc/input/edge/ — MB-OPC 边段前端

> 边段型 OPC 方法复用的高性能输入构造层。公共入口 `prepare_problem()` 产出冻结的 `MBOPCProblem`；此后每轮迭代只更新一个一维位移数组，不重建参考几何。

### 6.1 `opc/input/edge/__init__.py` — 公共导出

导出：`prepare_problem`、`fragment_edges`、`reconstruct_contours`/`reconstruct_region`、`edge_probe_points`、类型 `FragmentationConfig`/`MBOPCProblem`/`SegmentBatch`/`SegmentGeometry`。归属构造为 builder 私有步骤。

### 6.2 `opc/input/edge/types.py` — 边段数据契约

模块职责：MB-OPC 紧凑控制边段、物化几何和配置数据契约。私有辅助 `_vector`/`_matrix` 做一维/二维数组规范化。类型别名 `IntArray`/`Int32Array`/`FloatArray`。

#### `FragmentationConfig`（分段配置，DBU）
- `corner_length_dbu: float` — 拐角部短段长度（正）。
- `max_segment_length_dbu: float` — 中段最大长度（正，且 ≥ 2×corner）。
- `max_displacement_dbu: float` — 单段绝对法向位移上限（非负）。
- `miter_limit: float = 4.0` — 拐角 miter 限值（≥1.0）；超限时改用 bevel。
- 校验：均为有限实数；长度为正；`max_segment_length ≥ 2×corner_length`；`miter_limit ≥ 1.0`。

#### `SegmentGeometry`（物化的当前端点 + 法向）
按需物化的控制边段端点和外法向（`materialize()` 的返回）。
- `starts: FloatArray` — 形状 `(N,2)`，每段当前起点。
- `ends: FloatArray` — 每段当前终点。
- `normals: FloatArray` — 每段单位外法向（指向空区）。
- 校验：三数组同长、连续 float64。

#### `SegmentBatch`（紧凑控制边段）
通过数学边索引和参数区间保存控制边段，避免重复几何元数据。**只常驻求解所需字段**（已删除旧的稳定 key、排序查找表、外部更新批次等无当前调用方的结构）。
- `contours: ContourBatch` — 固定参考轮廓的唯一数值所有者。
- `edge_next_ids: Int32Array` — 每条数学边终点顶点索引。
- `edge_polygon_ids: Int32Array` — 每条数学边所属 Polygon，用于 tile 子集选择。
- `edge_normals: FloatArray` — 每条数学边的外法向（边级，长度==数学边数）。
- `ring_segment_offsets: IntArray` — 每环在 segment 序列中的起始偏移（长度==ring_count+1），用于重建时定位环边界。
- `edge_ids: Int32Array` — 每段所属数学边的下标（int32，是 segment 身份契约）。
- `t0: FloatArray` — 每段在数学边上的起点参数（`[0,1]`）。
- `t1: FloatArray` — 每段在数学边上的终点参数（`[0,1]`，`t1>t0`）。
- 校验：两个 edge cache 与 contour 拓扑完全一致；edge_normals 长度==数学边数；ring offsets 首 0 末 segment_count 且每环≥1 段；edge_ids/t0/t1 长度==segment_count；参数范围和法向有限。
- 属性 `segment_count -> int` — 段数（`len(edge_ids)`）。
- 属性 `persistent_nbytes -> int` — 当前批次新增常驻 NumPy 数组总字节数（诊断用）。
- 方法 `materialize(displacements=None) -> SegmentGeometry`
  - **功能**：按全局稳定顺序生成全部 segment 的当前端点和外法向。**这是迭代热路径上端点/法向的唯一来源。**
  - **输入**：可选 `displacements` — 与 segment 对齐的一维位移向量（每段沿其法向平移）；`None` 表示零位移（参考几何）。
  - **输出**：`SegmentGeometry`（starts/ends 已叠加 `normal*displacement`，normals 不变）。
  - **实现**：由 `contours.vertices`、`edge_next_ids[edge_ids]` 和 `t0/t1` 参数化重建端点；位移非零时叠加法向位移。
  - **异常**：`displacements` 长度不符或含非有限值抛 `ValueError`。

#### `MBOPCProblem`（多轮可复用的固定参考）
聚合固定参考与重建配置；每轮变化量只有一维位移向量。
- `physical_mask: PhysicalMask` — 合并物理 Region、Layer 和 ROI。
- `config: FragmentationConfig` — 分段与位移约束。
- `segments: SegmentBatch` — 紧凑控制边段。
- `grid: RectilinearCoreGrid` — 紧凑规则切线和 halo；不常驻展开 CoreSpec。
- `owner_indices/core_offsets/member_segment_indices` — 唯一 owner 与 halo CSR。
- 校验：每个 segment 必须有 `[0,core_count)` 内唯一 owner，CSR 与成员索引范围合法。
- `core_count`、`persistent_nbytes` 属性；`segments_for_core(core_index)` 返回 CSR 视图。

### 6.3 `opc/input/edge/builder.py` — `prepare_problem`

#### `prepare_problem(batch, layer, config, grid=None) -> MBOPCProblem`
- **功能**：一次性准备可供多轮 MB-OPC 复用的完整前端问题。**架构中心**。
- **输入**：`batch: RegionBatch`；`layer: LayerSpec`；`config: FragmentationConfig`；`grid: RectilinearCoreGrid | None`（默认用 `batch.query_box` 建单 core 网格）。
- **输出**：冻结的 `MBOPCProblem`。
- **顺序**：`normalize_physical_mask` → `extract_contour` → `fragment_edges` →（默认建单 core 网格）→ `_build_ownership` → `MBOPCProblem`。
- **要点**：默认单 core 仍走与整 reticle 完全相同的规则网格代码，避免第二套显式 core 校验语义；不预生成图片/文件/探针缓存；**必须在 `with LayoutDB.open(...)` 内调用**（不变量 1）。

### 6.4 `opc/input/edge/fragmentation.py` — 边段切分 + 外法向

模块职责：把物理数学边批量切分为按全局拓扑顺序排列的 MB-OPC 控制边段。

#### `_outward_normals(contours, edge_next_ids, edge_ring_ids, ring_is_hole, lengths) -> ndarray`（私有）
- **功能**：根据环绕向与 hole 标志，解析计算从材料指向空区的单位外法向。
- **依据**：用叉积判断每环 CCW/CW；外轮廓顺时针时材料在边右侧→外法向取左法向；hole 逆时针时材料在环外侧→同样取左法向；其余两种绕向对称取右法向。

#### `fragment_edges(contours: ContourBatch, config: FragmentationConfig) -> SegmentBatch`
- **功能**：按角部短段 + 均衡中段策略，向量化切分全部物理数学边。
- **输入**：`contours: ContourBatch`；`config`。
- **输出**：`SegmentBatch`（edge_ids/t0/t1/ring_segment_offsets/edge_normals）。
- **切分策略**：
  - 短边（`length ≤ 2×max`）：均分为 `ceil(length/max)` 段。
  - 长边（`length > 2×max`）：两端各一段长度 `corner`，中间均分剩余。
- **容量保护**：单边段数或总段数超过 `int32` 上限抛 `OverflowError`（这是“整 reticle 必须分块”的硬墙，见 `doc/design_review.md` 4.1）。
- **优化**：构造期 `edge_offsets`/`lengths` 完成使命后不进入常驻 `SegmentBatch`；诊断需要时再推导。

### 6.5 `opc/input/edge/ownership.py` — 私有归属构造

#### `_build_ownership(segments, grid) -> tuple[np.ndarray, ...]`
- **功能**：利用网格切线直接展开每段覆盖的有限 core 范围，返回 owner、core offsets 和 member indices。
- **输入**：`segments`；`grid`。
- **输出**：三组连续数组，由 `prepare_problem` 直接放入 `MBOPCProblem`。
- **owner**：用段中点 `grid.locate_points(midpoints)` 得唯一 owner（不变量：每段一个 owner）。
- **halo membership**：对每段 bbox 四向扩 `halo_dbu`，在 `x_cuts/y_cuts` 上 `searchsorted` 定位首尾候选 core，展开二维 core 范围。**复杂度随实际 halo 邻居数增长，不建 S×C 矩阵。**
- **CSR**：按 core_index `argsort`（稳定）排序成员，`bincount` 建 `core_offsets`。
- **实现**：直接由 contour、edge cache 和参数区间生成参考端点，不调用 `segments.materialize()`，并在展开 membership 前释放 S×2 临时数组。

### 6.6 `opc/input/edge/sampling.py` — `edge_probe_points`

#### `edge_probe_points(starts, ends, normals, distance_dbu) -> tuple[ndarray, ndarray]`
- **功能**：返回每条边段中点沿负/正外法向偏移后的 **inner** 与 **outer** 坐标。求解器与诊断共用此唯一实现，避免显示距离与求解距离分叉。
- **输入**：`starts/ends/normals` — 同形 `(N,2)` 数组；`distance_dbu` — 正有限探针距离。
- **输出**：`(inner, outer)`，均为 `(N,2)` 连续数组。
- **约定**：`inner = midpoint - normal*distance`（材料侧/内侧）；`outer = midpoint + normal*distance`（空区侧/外侧）。该约定是 EPE 方向判定的基础（见 §9）。
- **异常**：形状不符或距离非正有限抛 `ValueError`。

### 6.7 `opc/input/edge/reconstruction.py` — 矢量重建

模块职责：根据控制边段法向位移重建闭合 Polygon 环和物理 Region。

#### `_validated_displacements(segments, displacements, config) -> ndarray`（私有）
- **功能**：规范化位移向量并在几何计算前做一次全局范围检查。
- **校验**：一维、长度==segment_count、有限、绝对值 ≤ `max_displacement_dbu`；否则 `ValueError`/`ReconstructionError`。

#### `reconstruct_contours(problem: MBOPCProblem, displacements) -> ContourBatch`
- **功能**：批量计算 junction，重建保留 polygon/hole 拓扑的整数轮廓。**零位移时必须与原物理 mask 完全一致（XOR 面积==0，不变量 4）。**
- **输入**：`problem`；`displacements`（一维，与 segment 对齐）。
- **输出**：`ContourBatch`（整数 DBU 顶点）。
- **关键逻辑**：
  - 同一数学边且位移相同→不输出内部切分点；位移不同→输出两端点形成 **jog**。
  - 原始拐角（跨数学边）→ 解析求交点；当 miter 距离超 `miter_limit` 或两边平行时改用 **bevel**（两点）。
  - 斜边参数点先保留浮点、最后统一取整，避免先取整偏离原直线产生 XOR 毛刺。
  - 去除环内连续重复点与重复闭合点，保持每环≥3 顶点。
  - 末尾 `validate_contours` 校验，非法抛 `ReconstructionError`。

#### `reconstruct_region(problem: MBOPCProblem, displacements) -> kdb.Region`
- **功能**：把重建轮廓转为 KLayout Region，并拒绝原生无效 Polygon。
- **输入/输出**：同上，返回 `kdb.Region`。
- **实现**：`contours_to_region(reconstruct_contours(...))` + `has_valid_polygons()` 检查。
- **异常**：重建无效抛 `ReconstructionError`。
- **要点**：core 只划分计算权，不裁最终 Polygon；最终矢量始终由全局位移统一重建，避免跨 core/斜边的多次整数裁剪接缝。

## 7. opc/iteration/mbopc/ — simple MB-OPC 流式求解器

> 基于边段 EPE 的简单同步 MB-OPC 迭代器。CPU 保存全局 `current`/`next_values` 位移，GPU/CPU 上每个 batch 只送当前 core+halo 的 mask/target/ownership 像素；owner 唯一写、halo 只读、整轮屏障后统一发布。

### 7.1 `opc/iteration/mbopc/__init__.py` — 导出

导出：`optimize`、`SimpleMBOPCConfig`、`IterationRecord`、`SimpleMBOPCResult`。

### 7.2 `opc/iteration/mbopc/types.py` — 配置/记录/结果契约

#### `SimpleMBOPCConfig`（迭代配置，已换算到 DBU/像素）
- `iterations: int` — 最大评价轮数（正整数）。
- `initial_step_dbu: float` — 初始位移步长（正有限）。
- `decay_every: int` — 每 N 轮把步长减半（正整数）。
- `epe_distance_dbu: float` — inner/outer 探针距离（正有限）。
- `pixel_dbu: int` — 一个光刻像素的 DBU 尺寸（正整数）。
- `canvas: int = 256` — 光刻画布边长（像素，须 ≤ 模型 canvas）。
- `batch_size: int = 64` — 单次送设备的 tile 数（显存不足时调小）。
- `target_cache_bytes: int = 512*1024*1024` — CPU target LRU 字节上限（0 关闭）。
- 校验：均为有效正数；浮点配置有限。

#### `IterationRecord`（单轮记录）
- `iteration: int` — 轮次下标。
- `step_dbu: float` — 本轮步长。
- `epe: int` — 本轮 EPE 违规段数。
- `l2: float` — ownership 像素 L2。
- `pvband: float` — ownership 像素 PVBand。
- `valid_probes: int` — 有效探针数。
- `ambiguous_probes: int` — 同时触发相反要求的探针数。
- `moved_segments: int` — 本轮发生位移的段数（已扣回滚）。
- `rejected_segments: int` — 被拓扑回滚的段数。
- `elapsed_seconds: float` — 本轮耗时。

#### `SimpleMBOPCResult`（最终结果）
- `best_displacements: NDArray[float64]` — 最佳一轮对应的全局位移。
- `records: tuple[IterationRecord, ...]` — 全部轮次记录。
- `best_iteration: int` — 最佳轮次下标。
- `stop_reason: str` — 停止原因：`iteration_limit` / `zero_epe` / `no_legal_update`。

### 7.3 `opc/iteration/mbopc/solver.py` — `optimize`

模块职责：流式执行同步 owner-only 的简单 EPE 驱动 MB-OPC。

#### 私有辅助函数

- `_subset_contours(contours, polygon_ids) -> ContourBatch` — 直接索引 `polygon_ring_offsets`，批量提取完整 Polygon 的 hull/hole rings，只分配本 tile 选中的 ring/vertex。
- `_polygon_ids_for_core(problem, core_index) -> ndarray` — 经 `segments_for_core`（halo）取 edge→polygon_id 去重，返回一个 core context 内可能受位移影响的稳定 Polygon ID。
- `_TargetCache(max_bytes)` — 按字节上限的 target tile LRU；`get(key)` 命中提升、`put(key,value)` 超限驱逐最旧。缓存用 `uint8`（float32 的 1/4），命中时恢复到 `[0,1]`。
- `_target_tile(problem, core_index, core, config, cache) -> ndarray` — 使用 solver 一次展开的 CoreSpec，读缓存或栅格化固定参考 mask。
- `_current_tile(problem, contours, displacements, core_index, core, polygon_ids, target, config) -> ndarray` — 用参考 tile 加邻近 Polygon 差分生成当前 mask；局部位移全零时跳过轮廓子集重建。
- `_owner_indices(problem) -> tuple[ndarray, ...]` — 一次性建立每 core 的 owner segment 索引，供所有轮次复用。
- `_ring_signed_areas2(contours) -> ndarray` — 向量化返回每环的两倍有符号面积（shoelace），不逐环遍历。
- `_preserves_reference_topology(reference, candidate, reference_areas=None) -> bool` — 拓扑守卫：检查 `polygon_ring_offsets` 不变、环绕向未翻转，且每个 hole 仍完整包含在首 hull 内。

#### `optimize(problem: MBOPCProblem, model: ICCAD13Lithography, config: SimpleMBOPCConfig) -> SimpleMBOPCResult`
- **功能**：以 tile batch 评价当前状态，并在轮次屏障后统一发布 owner 更新；保存最佳位移。
- **输入**：`problem`；`model`（光刻模型，`canvas ≥ config.canvas`）；`config`。
- **输出**：`SimpleMBOPCResult`。
- **前置校验**：`config.canvas ≤ model.config.canvas`；每 core context 须能放入 `config.canvas`。
- **每轮流程**：
  1. `step = initial_step * 0.5^(iteration//decay_every)`（步长衰减）。
  2. 复制 `next_values = current.copy()`，建立 `written` 布尔位。
  3. **按 batch_size 流式处理 core**：每 core 取 target（缓存）、current（差分）、ownership 画布 → 栈成 batch tensor → `model(mask)` → `evaluate_process_window`（只在 ownership 像素计 L2/PVBand）。
  4. **EPE 方向**：对每 core 的 owner segment 用 `edge_probe_points`（参考几何）生成 inner/outer → `evaluate_edge_probes` 得 `directions ∈ {-1,0,+1}`。
  5. **owner-only 写**：检测 `written[segments]` 是否已被同轮其它 core 写过（否则 `RuntimeError`），置位后 `next_values[segments] = clip(current[segments] + directions*step, ±max_displacement)`。
  6. batch 末尾释放 tile tensor，`current` 未变（后续 batch 不见已算的 next）。
  7. 评分 `score=(total_epe, total_l2, total_pvb)`，更新最佳（记录的是产生该 score 的 `current`）。
  8. **拓扑守卫**（非末轮且发生位移）：重建候选轮廓，`_preserves_reference_topology` 不通过则**整轮回滚**（`rejected=moved`，`next_values=current`）。
  9. **屏障**：全部 core/batch 完成且候选合法后，才 `current = next_values`，下一轮同时看到新位移。
- **停止条件**：`total_epe==0`（`zero_epe`）/ 达到 `iterations`（`iteration_limit`）/ `moved==0 或 rejected==moved`（`no_legal_update`）。
- **已知语义（见 `doc/design_review.md` 0.2.A）**：末轮在提交语句之前 `break`，故**最后一轮算出的位移不提交**、不进入 `best_displacements` 候选。后果：`iterations=N` 最多应用 N−1 次位移，`iterations=1` 应用 0 次。这是“返回最佳已评估态”的设计选择，使用时请注意。

## 8. lithography/ — 光刻模型

> 与具体 OPC/ILT 方法解耦的光刻模型层。当前为 OpenILT ICCAD13 Hopkins 部分相干模型，可整体替换。

### 8.1 `lithography/__init__.py` — 导出

导出：`ICCAD13Config`、`ICCAD13Lithography`、`LithographyResult`。资产位于 `lithography/assets/iccad13/*.pt`、配置位于 `lithography/config/iccad13.txt`。

### 8.2 `lithography/iccad13.py` — ICCAD13 模型

模块职责：基于 OpenILT ICCAD13 Hopkins 核实现可批处理的三工艺角光刻仿真。

> **Windows DLL 注意**：模块顶部在 `os.name=="nt"` 时把 `<env>/bin` 加入 DLL 搜索目录（PyTorch NVRTC 运行时所在），句柄在进程生命周期内保留；非 Windows 不执行。

#### `ICCAD13Config`（模型数值配置）
- `kernel_count: int` — Hopkins 核数量。
- `target_density: float` — 目标光刻胶阈值密度。
- `print_threshold: float` — “已印”判定阈值（`(0,1)`）。
- `print_steepness: float` — sigmoid 陡度。
- `dose_max/dose_min/dose_nominal: float` — 最大/最小/标称剂量（须 `min ≤ nominal ≤ max`）。
- `canvas: int` — 固定画布边长（像素）。
- `resolution: int` — 仿真分辨率。
- 类方法 `from_file(path) -> ICCAD13Config` — 读“名称 值”配置文件，校验全部必需字段与数值范围。

#### `LithographyResult`（三工艺角胶图像）
- `nominal: torch.Tensor` — 标称工艺角（dose_nominal, focus 核）。
- `maximum: torch.Tensor` — 最大工艺角（dose_max, focus 核）→ 印得最多。
- `minimum: torch.Tensor` — 最小工艺角（dose_min, defocus 核）→ 印得最少。
- PVBand = `maximum − minimum` 表征工艺窗口变化。

#### `ICCAD13Lithography(nn.Module)`（Hopkins 模型）
- `__init__(config_path=None, asset_dir=None, device=None)` — 加载配置与四个 kernel/scale 资产到指定设备；`device=None` 或 `"auto"` 时自动选 CUDA/CPU。kernel/scale 注册为 buffer（随 `.to()` 迁移、不被优化器训练）。资产路径相对本模块解析，任意工作目录均可运行。
- 属性 `device -> torch.device` — 当前 buffer 所在设备。
- `forward(mask: torch.Tensor) -> LithographyResult` — **功能**：执行 mask→aerial→连续光刻胶的三工艺角前向。接受 `[H,W]` 或 `[B,H,W]`；居中补零到 `canvas`、按需缩放到 `resolution`、三工艺角 `_aerial`、`sigmoid(steepness*(img-density))` 恢复尺寸。单张输入时返回的三个张量去掉 batch 维。
- `_aerial(mask, dose, kernels, scales) -> Tensor`（私有）— 一个剂量/焦距条件下的 Hopkins 部分相干 aerial image：`fft2(dose*mask)` → `_kernel_multiply` → `ifft2` → 加权 `Σ scale_k·|field_k|²`。
- `_kernel_multiply(kernels, mask_fft, kernel_count) -> Tensor`（私有）— 把中心原点 kernel 的四象限映射到 FFT 频谱四角（四次批量赋值，GPU 热路径）。
- `_prepare_mask(mask)` / `_restore_size(image, padding)`（私有）— 居中补零/缩放与逆操作，保证输出与输入 tile 位置 1:1 对齐。
- `_load_kernels(path, device)` / `_load_scales(path, device)`（静态）— 加载 H×W×K 资产转为 K×H×W 复数 / 一维 float32 权重。

> **移植不变量（见 `doc/design_review.md` 0.2.B）**：`_aerial` 对 `fft2`/`ifft2` 均用 `norm="forward"`，绝对强度依赖随附 OpenILT `.pt` 资产在同一约定下生成。不要改动 `norm=` 或重生成资产而不同时校验参考 aerial。

## 9. evaluation/ — 评价指标

> 可由 OPC、ILT 与独立验证共同使用的光刻评价指标。向量化、批量、设备无关。

### 9.1 `evaluation/__init__.py` — 导出

导出：`QualityMetrics`、`EPEEvaluation`、`evaluate_process_window`、`evaluate_edge_probes`。

### 9.2 `evaluation/metrics.py` — 指标实现

#### `QualityMetrics`（工艺窗口质量）
- `l2: float` — ownership 像素上 `(nominal − target)²` 之和。
- `pvband: float` — ownership 像素上 `(maximum − minimum)²` 之和。

#### `EPEEvaluation`（逐边段 EPE）
- `valid: torch.Tensor` — 每段探针是否有效（bool）。
- `inner_violations: torch.Tensor` — inner 探针违规（参考应有材料却没印）。
- `outer_violations: torch.Tensor` — outer 探针违规（参考应无材料却印出）。
- `ambiguous: torch.Tensor` — 同时触发相反要求的探针。
- `directions: torch.Tensor` — 每段法向移动方向 `{-1,0,+1}`（int8）。
- 属性 `violation_count -> int` — 至少一个有效探针违规的段数。

#### `_aligned_images(*images)`（私有）
把二维图提升为 batch，拒绝形状/设备不一致。

#### `evaluate_process_window(target, nominal, maximum, minimum, ownership_mask=None) -> QualityMetrics`
- **功能**：只在唯一 ownership 像素上累计连续 L2 和 PVBand；halo 像素不重复计入全局指标。
- **输入**：四张 `[H,W]` 或 `[B,H,W]` 同形同设备张量；可选 `ownership_mask`（同形 bool，或 `None` 表示全选）。
- **输出**：`QualityMetrics`（两个标量）。
- **实现**：布尔索引一次完成筛选，只回传两个标量到 CPU，不回传整张曝光图。

#### `evaluate_edge_probes(target, nominal, batch_indices, inner_xy, outer_xy, threshold=0.499) -> EPEEvaluation`
- **功能**：批量评价 inner/outer 探针并生成 `-1/0/+1` 法向移动方向。
- **输入**：`target`/`nominal`（`[B,H,W]`）；`batch_indices`（每段所属 batch，int64）；`inner_xy`/`outer_xy`（每段 `[N,2]`，列 0=x 列 1=y）；`threshold`。
- **输出**：`EPEEvaluation`。
- **方向判定逻辑**（与 §6.6 inner/outer 约定一致）：
  - `valid = 画布内 & inner≠outer & target(inner)有材料 & target(outer)无材料`（探针未穿过对侧边界）。
  - `inner_violations = valid & nominal(inner)未印` → 边太靠内 → **外扩 `+1`**。
  - `outer_violations = valid & nominal(outer)印出` → 边溢出 → **内缩 `-1`**。
  - 两者同时违规 → `ambiguous`，方向保持 `0`（单边动作无法可靠解决）。
- **实现**：探针坐标 `round` 取整后批量索引；越界用 clamp + `in_bounds` 掩码保证安全。
- **异常**：探针索引/坐标不对齐抛 `ValueError`。

## 10. opc/diagnostics.py — 诊断物化

> **只在显式请求时才执行**的 OPC 数值快照、版图、边界标注图与确定性几何图集。不进入迭代热路径；求解器不反向依赖任何输出格式。

#### `save_problem_npz(problem, displacements, output_path) -> Path`
- **功能**：以 segment 全局索引为对齐契约，原子保存前端诊断快照（NPZ，format_version=3）。
- **输入**：`problem: MBOPCProblem`；`displacements`（一维，长度==segment_count）；`output_path`。
- **输出**：规范化输出 `Path`。
- **内容**：轮廓两级 CSR、edge next/polygon cache、edge normals、segment 参数、位移、grid cuts/halo 和 owner/membership CSR；不保存展开 core boxes 或旧 edge 派生列。
- **可靠性**：同卷临时文件 + `os.replace`；异常清理。
- **注**：NPZ 是**当前进程** problem 的快照，不是跨 remesh/跨版本的持久身份协议；无对应加载器（见 `doc/design_review.md` 4.8）。

#### `write_debug_gds(reference, reconstructed, output_path, dbu_um, layer, datatype=0) -> Path`
- **功能**：把参考与重建 mask 写入两个独立顶层 Cell（`REFERENCE`/`RECONSTRUCTED`），便于版图工具比较。
- **输入**：两个 `kdb.Region`；`output_path`（`.gds`）；`dbu_um`；`layer`/`datatype`。
- **输出**：输出 `Path`。原子写出。

#### `_line_arrays(starts, ends, normals)` / `_sample_array(samples, name)`（私有）
规范化绘图线段与可选探针坐标，统一检查形状与有限性。

#### `render_boundary_overlay(region, layer, box, dbu_um, starts, ends, normals, output_path, owners=None, inner_samples=None, outer_samples=None, cores=(), max_dimension=1200, max_labels=80, max_samples=600) -> Path`
- **功能**：保存含 mask、segment、法向、EPE 探针和 core 归属的 PNG。
- **输入**：`region: kdb.Region`；`layer`/`box`/`dbu_um`；线段 `starts/ends/normals`（`(N,2)`）；可选 `owners`（每段 owner core）、成对的 `inner_samples/outer_samples`、`cores`。
- **输出**：PNG `Path`。
- **实现**：用 `render_region_batch` 生成灰度底图 → 转 RGB → 最多 4× 最近邻放大 → 用 `ImageDraw` 绘 core 框（owner 颜色）、segment（owner 颜色）、法向箭头、抽样标签 `S{idx}/C{owner}`、成对 cyan inner / red outer 探针。原子保存。
- **用途**：求解器与前端都用它产诊断图。

#### `build_geometry_cases() -> dict[str, kdb.Region]`
- **功能**：返回覆盖正交、孔洞、斜边、负坐标和接触语义的确定性几何用例（5 个）。
- **输出**：`{orthogonal_concave, hole_overlap, diagonal_angles, negative_cross_core, overlap_corner_touch}` → `kdb.Region`。

#### `_case_batch(name, region, layer)` / `_case_grid(box)`（私有）
为单用例生成带留白的 `RegionBatch` / 中心 2×2 core 网格。

#### `run_geometry_suite(output_dir, write_images=True, probe_distance_dbu=8.0) -> dict`
- **功能**：对全部几何用例运行零位移往返、分段上限、归属和探针图集验证。
- **输入**：`output_dir`；`write_images`；`probe_distance_dbu`。
- **输出**：汇总 dict（每用例 polygon/ring/edge/segment/core/membership 数、最大段长、XOR 面积等）+ 写出每用例 PNG 与 `geometry_suite.json`。
- **断言**：零位移 XOR==0、最大段长 ≤ config、无无 owner 边段；否则 `ValueError`。

## 11. 根脚本（命令行入口）

> 三个根脚本均**无需 `pip install`**，直接 `python run_xxx.py` 运行。共享模式：`build_parser()`→`main()`→`run()`→`print_text()`/JSON，把可预期领域异常转为退出码 2。所有 nm 参数进入几何内核前按版图 DBU 换算。

### 11.1 `run_layout_geometry.py` — Layout/Geometry CLI

模块职责：直接读取 GDS/OASIS，按 Layer/ROI 查询，并可导出 ownership Patch / 灰度 PNG。

- `parse_layer(value) -> LayerSpec` — 解析 `layer/datatype` 或 `layer:datatype` CLI 参数。
- `build_parser() -> ArgumentParser` — 参数：`layout`、`--top`、`--layer`(可重复)、`--box`、`--diagnostics`、`--arrays`、`--output`、`--png`、`--show-image`、`--pixel-size-nm`、`--max-image-pixels`、`--json`。
- `run(args) -> dict`
  - **功能**：执行一次单文件、单 ROI 的完整 Layout→Geometry 数据流。
  - **流程**：`LayoutDB.open` → `query(layers, box).materialize(diagnostics)` → 逐层统计 polygon/area/bbox（`--arrays` 时额外生成 ContourBatch；数学边数直接等于闭环顶点数）→ 可选 Patch/PNG。
  - **输出**：JSON 兼容 dict（源、top、dbu、box、每层统计、可选 output/image）。
- `print_text(result)` — 紧凑中文打印。
- `main(argv=None) -> int` — 解析、运行；`LayoutError/GeometryError/OSError/ValueError` → 退出码 2；`--json` 输出 JSON 否则文本；成功 0。

### 11.2 `run_mbopc_frontend.py` — MB-OPC 前端验证 CLI（不跑光刻）

模块职责：无需安装即可验证 OPC 公共层与 MB-OPC 前端全部功能。无 `--layout` 时跑合成多图形案例。

- `parse_layer(value) -> LayerSpec` — 同上。
- `build_parser() -> ArgumentParser` — 参数：可选 `layout`、`--layer`、`--box`、互斥 `--grid COLUMNS ROWS`（默认 2 1）/`--tile-size-nm`、`--halo-nm`、`--corner-nm`、`--segment-nm`、`--max-displacement-nm`、`--demo-displacement-nm`、`--probe-distance-nm`、`--output-dir`、`--json`、`--skip-geometry-suite`。
- `_demo_batch() -> (RegionBatch, LayerSpec, float)` — 构造含重叠、孔洞、凹角、斜边、跨 core 长边的合成物理层。
- `_axis_cuts(start, end, count)` — 按数量均分 cuts（严格递增）。
- `_axis_cuts_by_size(start, end, tile_size_dbu)` — 按固定步长生成 cuts，末 tile 裁到终点。
- `_load_database_batch(args, database) -> (RegionBatch, LayerSpec, float)` — DB 生命周期内选层、定范围、物化。
- `_prepare_input_problem(args, batch, layer, dbu_um) -> (MBOPCProblem, RectilinearCoreGrid)` — 按 CLI 物理尺寸建 core 网格、分段配置，调 `prepare_problem`。
- `_demo_displacements(problem, displacement_dbu) -> (ndarray, ndarray)` — 为每个有 owner 边段的 core 选一段做示范位移，返回全局对齐位移及变化索引（直接从 owner_indices 反查，无非 owner 写入）。
- `run(args) -> dict`
  - **功能**：执行一次完整 MB-OPC 前端演示，返回可序列化摘要并原子写 `summary.json`。
  - **流程**（无 layout 时合成；有 layout 时 `with LayoutDB.open(...)` 内物化 + `prepare_problem`）→ `_demo_displacements` → `materialize` → `edge_probe_points`（参考几何）→ 两次 `reconstruct_region`（零位移参考 + 移动后）→ **校验**：零位移 XOR==0、core ownership 覆盖完整无正面积重叠 → `save_problem_npz` + `write_debug_gds` + `render_boundary_overlay` + `run_geometry_suite`（可跳过）→ 汇总 counts/memory/timing/verification/artifacts。
  - **输出**：JSON 兼容 dict。
- `print_text(result)` / `main(argv=None) -> int` — 同模式；`LayoutError/OPCError/OSError/ValueError` → 2。

### 11.3 `run_mbopc.py` — 完整 MB-OPC 主程序

模块职责：直接从 GDS/OASIS 运行流式 simple MB-OPC 并保存最佳全局结果（含真实光刻模型）。

- `parse_layer(value) -> LayerSpec` — 同上。
- `build_parser() -> ArgumentParser` — 参数：可选 `layout`（默认 `TestReticle/simple.gds`）、`--top-cell`、`--layer`、`--box`、`--tile-size-nm`(默认 1024)、`--halo-nm`(默认 512)、`--pixel-nm`(默认 8)、`--corner-nm`、`--segment-nm`、`--max-displacement-nm`、`--iterations`(默认 8)、`--step-nm`、`--decay-every`(默认 4)、`--epe-distance-nm`、`--batch-size`(默认 8)、`--target-cache-mb`(默认 512)、`--device`(auto/cpu/cuda)、`--output-dir`(默认 `output/mbopc`)、`--preview`、`--json`。
- `_exact_dbu(value_nm, dbu_nm, name, allow_zero=False) -> int` — 把必须对齐格点的物理长度**严格**换算为整数 DBU；不能精确表达则 `ValueError`（不变量 5）。
- `_axis_cuts(start, end, tile_dbu)` — 按固定 DBU 步长生成 cuts，末段裁到终点。
- `_select_layer(database, requested) -> LayerSpec` — 选显式层；单层版图自动选；多层未指定则报错。
- `_atomic_json(path, value) -> Path` — 目标目录内原子写 UTF-8 JSON。
- `run(args) -> dict`
  - **功能**：版图读取、前端准备、流式迭代、最佳结果全局一次重建。
  - **流程**：`with LayoutDB.open(...)` 内 `_select_layer` + `bbox` + `query.materialize()` → nm→DBU 精确换算（`pixel/tile/halo`，校验 `tile%pixel==0`、`halo%pixel==0`）→ `RectilinearCoreGrid` + `FragmentationConfig` + `prepare_problem`（**必须在上下文内**）→ `ICCAD13Lithography` + `SimpleMBOPCConfig` → CUDA 时 reset peak memory → `optimize` → `reconstruct_region(best_displacements)` → `write_debug_gds` + 可选 `render_boundary_overlay` → 汇总（counts/optimization 含全部 records/memory/gpu_peak/timing/verification/artifacts）→ `_atomic_json(summary.json)`。
  - **输出**：JSON 兼容 dict。
- `print_text(result)` / `main(argv=None) -> int` — 同模式；`LayoutError/OPCError/OSError/RuntimeError/ValueError` → 2。

## 附录 B. 坐标、单位与像素约定

- **DBU（数据库单位）**：版图整数坐标单位；`dbu_um` 是每个 DBU 的微米值（如 0.001 μm = 1 nm/DBU）。所有几何内核用整数 DBU；CLI 的 nm 参数需精确换算为整数 DBU，否则报错。
- **nm → DBU 换算**：`run_mbopc.py` 用 `_exact_dbu` 严格换算（`round(nm/dbu_nm)`，必须 `isclose`），且要求 `tile-size-nm`、`halo-nm` 是 `pixel-nm` 的整数倍——避免相邻 tile 用不同物理晶格。
- **像素栅格化方向（关键差异）**：
  - `geometry/raster.py`（PNG 展示）：图片第 0 行在**顶部**，`+Y` 朝上；分块内 `flipud`。
  - `opc/input/raster.py`（光刻模型）：第 0 行在**底部**，与探针 `(y-bottom)/pixel` 一致，**不**翻转。
  - 两者不可混用；探针坐标与 `ownership_canvas` 都按底朝上约定。
- **像素中心**：`ownership_canvas` 用像素中心 `(i+0.5)*pixel` 判定是否落在 core 内。
- **EPE 探针约定**：`inner = midpoint − normal·d`（材料侧/内侧），`outer = midpoint + normal·d`（空区侧/外侧）；外法向 `normal` 指向空区。`inner 违规 → +1 外扩`，`outer 违规 → −1 内缩`，`current + directions·step` 应用位移。
- **三工艺角**：nominal（dose_nom, focus）、maximum（dose_max, focus，印得最多）、minimum（dose_min, defocus，印得最少）；PVBand = max − min。

## 附录 C. 常见陷阱与 FAQ

1. **Region 变空 / 零计数**：`materialize()` 与 `prepare_problem()` 必须在 `with LayoutDB.open(...)` 内调用。离开上下文后原生 Region 失效（见 §1.3 不变量 1、`ERRORS.md`）。
2. **`iterations=N` 只应用 N−1 次位移**：末轮位移不提交（见 §7.3、`design_review.md` 0.2.A）。要 N 次有效位移需设 `iterations=N+1`，或改为末轮提交。
3. **改光刻 FFT `norm=` 后结果静默失真**：`iccad13._aerial` 的 `fft2`/`ifft2` 均用 `norm="forward"`，绝对强度依赖随附 OpenILT 资产同约定；改动须对照参考 aerial 校验（`design_review.md` 0.2.B）。
4. **两个 raster 方向相反**：展示用 `geometry/raster`（顶朝上），光刻用 `opc/input/raster`（底朝上）。混用会让 mask 上下颠倒。
5. **nm 参数报“不能精确表达”**：该 nm 值不能由版图 DBU 整除。换一个对齐格点的值，或调整 DBU。
6. **`owner=-1` 或越界**：`MBOPCProblem` 构造时直接拒绝，不能进入求解器。确保 `RectilinearCoreGrid` 覆盖全部 segment 中点。
7. **同轮 segment 被多 core 写**：触发 `RuntimeError`。唯一 owner 由私有 `_build_ownership` 生成，solver 再用 epoch/bitset 检测重复写入。
8. **拓扑回滚导致整轮无进展**：候选轮廓翻转绕向或 hole 逃逸时整轮回滚（`stop_reason=no_legal_update`）。检查 `max_displacement` 是否过大或初始 mask 是否合法。
9. **测试硬编码 `TestReticle` 坐标**：禁止。用 `tests/fixtures/layout_factory.py` 生成确定性 GDS（`ERRORS.md` ERR-...016）。
10. **`ruff check .` 误报**：`Test/klayout.ipynb` 是用户 notebook，越界。务必限定范围（附录 A）。
11. **大 reticle int32 上限**：`fragment_edges` 单边或总 segment 数超 `int32.max` 抛 `OverflowError`——这是“必须分块”的硬墙（`design_review.md` 4.1）。
12. **零位移重建 XOR ≠ 0**：说明轮廓方向/孔洞归属/分段连接有错。几何图集与前端验证都会断言此项为 0。
